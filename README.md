# 카톡 아카이브

카카오톡 단체방 대화를 **읽을 수 있는 아카이브**로 바꿔, 방 사람들만 보는 웹앱으로 발행한다.

카톡은 흘러간다. 어제 누가 공유한 그 도구 이름이 뭐였는지, 그 링크가 어느 대화에 있었는지
찾을 방법이 사실상 없다. 그렇다고 대화 전문을 검색 가능한 형태로 어딘가에 올려두는 것은
다른 문제를 만든다 — 방에서 오간 말은 그 자리에 있던 사람들끼리 한 말이다.

그래서 이 저장소는 한 가지 판단 위에 서 있다.

> **방의 가치는 오간 말이 아니라 그 안의 내용이다.**

대화 원문은 발행하지 않는다. 발행하는 것은 주제별로 묶은 **요약과 결과물**이다 —
무슨 이야기가 오갔는지, 어떤 도구와 앱이 나왔는지, 누가 무엇을 만들었는지,
그때 공유된 링크·사진·파일은 무엇인지.

---

## 무엇을 만드나

카톡이 만들어 주는 대화 내보내기 txt 한 장에서 출발해 이런 화면들이 나온다.

| 화면 | 내용 |
|---|---|
| 홈·타임라인 | 날짜순 주제 흐름. 각 주제는 제목·요지·본문 보고서 |
| 관계망 | 사람–앱–도구–주제를 잇는 지식 그래프 |
| 태그 | 주제를 가로지르는 태그 색인 (표기가 다른 같은 태그는 합친다) |
| 갤러리·자료 | 대화에서 오간 사진·동영상·첨부 파일 |
| 통계 | 참여·주제 분포 |
| 내 글 | **본인이 쓴 글만** 원문으로. 무엇을 지울지 고르라고 있는 화면이다 |
| 관리자 | 열람 신청 승인, 삭제 요청 처리, 지금 갱신 |

## 어떻게 도나

```
카카오톡 (Ctrl+S 대화 내보내기)
   ↓  inbox/*.txt
증분 반영            새 메시지만 골라 원장(messages.jsonl)에 덧붙인다
   ↓
주제 분류 (LLM)      미분류 스레드만 — 파이프라인에서 유일한 LLM 칸
   ↓
발행본 생성          요약·관계망·태그·갤러리로 재구성, 개인정보 마스킹
   ↓
테스트               정합성 검사. 여기서 실패하면 발행하지 않는다
   ↓
Firestore 적재       달라진 문서만 (해시 비교)
   ↓
웹앱                 Firebase Hosting + Firestore 보안 규칙
```

매일 밤 작업 스케줄러가 [`scripts/run_daily.ps1`](scripts/run_daily.ps1)을 돌리고,
관리 탭의 '지금 갱신' 버튼은 [`scripts/refresh_watcher.js`](scripts/refresh_watcher.js)를
통해 같은 스크립트를 부른다. 자세한 것은 [docs/AUTOMATION.md](docs/AUTOMATION.md).

## 설계에서 고집한 것

**화면을 긁지 않는다.** 카톡 대화 목록은 커스텀 컨트롤이라 접근성 API로 읽히지 않고,
가상 스크롤이라 화면 밖 메시지는 존재하지도 않는다. 대신 카톡이 제공하는 '대화 내보내기'가
클라이언트가 가진 대화를 그대로 txt로 써 준다. 자동화는 **`Ctrl+S`를 보내는 것까지만** 하고,
나머지는 결정론적 코드가 처리한다. 메뉴를 클릭하지 않는 이유도 있다 — `대화 내용` 바로
아래 50px에 `채팅방 나가기`가 있다.

**LLM은 한 칸만 쓴다.** 파싱·증분 병합·발행은 코드가 더 정확하고 싸고 안정적이다.
다만 "이 대화가 어느 주제인가"는 코드가 답할 수 없어서 그 한 칸만 맡긴다. 그래서 이 단계는
파이프라인에서 **유일하게 실패가 허용되는** 칸이다. LLM 장애가 그날 타임라인·통계·삭제 요청
반영을 통째로 날려서는 안 된다.

**반쪽으로 발행하지 않는다.** 테스트가 적재보다 **앞**에 있다. 예전에는 뒤에 있었고,
그러면 검사가 잘못된 발행을 확인해 주는 꼴이 된다. 실패하면 그날 발행을 건너뛰고 원본은
그대로 남는다 — 고친 뒤 다시 돌리면 된다.

**모를 때는 발행하는 쪽으로 기운다.** 자식 스크립트의 신호를 못 읽었을 때 '변경 없음'으로
넘기면 삭제 요청이 조용히 묻힌다. 불필요한 발행은 거의 무료지만(적재는 달라진 문서만 쓴다),
올릴 것을 안 올리면 화면이 거짓말을 한다.

**되돌릴 수 없는 쪽을 조심한다.** 원장과 보고서 원본은 고치지 않는다. 무엇을 감출지는
발행 정책이므로, 정책이 바뀌면 다시 발행하면 된다. 원본을 고치면 "원래 뭐였는지"를 확인할
방법이 사라진다.

## 개인정보

이 저장소가 다루는 것이 사람들의 대화라서, 여러 겹으로 막는다.

- **원문 미발행** — 멤버가 보는 것은 요약과 결과물이다. 예전에는 원문이 문서에 실려 나가
  화면에 안 보여도 devtools로 전부 읽혔다. 지금은 애초에 발행하지 않는다.
- **발행 단계 마스킹** — 전화·이메일·주민번호·카드번호를 찾아 가린다. 정규식만으로는
  오탐이 진짜의 5배였다(실측: 25건 중 21건이 뉴스 기사 ID·상품코드·예시 번호). 그래서
  URL 구간 제외 → 예시 사전 → 근접 키워드, 세 겹으로 거른다. [`scripts/pii.py`](scripts/pii.py)
- **사진 OCR 검사** — 명함·안내문이 찍힌 사진을 발행 전에 판정한다.
- **본인 글만 본인에게** — 남의 원문은 아무도 못 본다. 관리자 원장은 가리지 않는다,
  오탐을 되돌릴 근거가 사라지기 때문이다.
- **삭제 요청** — 제외된 메시지는 발행본에 애초에 들어가지 않는다. "숨김"이 아니라 "미발행".

보안 규칙은 기본 차단이고([`firestore.rules`](firestore.rules)), 클라이언트 쓰기는
전면 금지다. 적재는 Admin SDK로만 한다.

### 이 저장소에 **없는** 것

대화 데이터·명부·자격증명은 하나도 커밋되지 않는다.

```
output/                 원장·주제·보고서·관계망 (전부)
config/members.json     멤버 이메일
config/pii_allow.json   감추지 않을 연락처 — 그 자체가 연락처 목록이다
assets/                 사진·동영상·첨부
serviceAccountKey.json  Firebase 서비스 계정 키
KakaoTalk_*.txt         내보내기 원문
```

[`tests/test_repo_is_publishable.py`](tests/test_repo_is_publishable.py)가 이것을 검사로
지킨다. 코드에 실명·실제 연락처가 들어오면 실패한다.

**검사 자료를 만들 때는 지어낸 이름과 연락처를 쓴다.** 실제 대화에서 값을 집어오는 것이
가장 자연스러워서 한 번 그렇게 굳은 적이 있다 — 발행본에서는 공들여 가리면서 정작
저장소에는 원본이 있었다.

## 돌려보기

파이썬 쪽은 표준 라이브러리로 도는데, 사진·아이콘을 다루는 몇 스크립트만 Pillow를 쓴다
(동영상 미리보기에는 `ffmpeg`이 PATH에 있어야 한다 — 없으면 그 단계만 건너뛴다).
적재는 Node 와 `firebase-admin`을 쓴다.

```bash
pip install pillow
npm install
```

```bash
python -m unittest discover -s tests    # 파이썬 검사
npm test                                # 적재 로직 검사
```

Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8`을 붙인다.

```powershell
powershell -File scripts\run_daily.ps1 -SkipExport -DryRun   # 확인만
powershell -File scripts\run_daily.ps1 -SkipExport           # inbox 의 txt 로 갱신
powershell -File scripts\run_daily.ps1                       # 내보내기까지 자동
```

배포는 [docs/DEPLOY.md](docs/DEPLOY.md)에 있다.

## 만든 방식

사회복지 실천가들의 바이브코딩 모임에서, 그 모임의 대화를 아카이브하려고 만들었다.
코드는 사람과 Claude가 함께 썼다. 주석이 유난히 많은데, 대부분은 "왜 이렇게 했는가"와
"이렇게 하지 않으면 무슨 일이 났는가"의 기록이다 — 실측 날짜가 붙은 것은 실제로 겪은 일이다.
