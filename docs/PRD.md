# PRD — welfareai.net
## AI 네이티브 사회복지 실천 커뮤니티

- 문서 버전: **v0.3 (2026-07-21)** — v0.2의 지식·에이전트 레이어 개정 (이력은 git 참조)
- 작성: 무지개 × Claude 설계 대화 기반
- 상태: 프로토타입 검증 반영 — 구성원 공유 전 내부 검토용
- **v0.3 핵심 변경**: **① 에이전트 개명·이원화** — `@지기`(운영·연결·자료 꺼내기, 읽기) / `@서기`(정리·기록, 쓰기), `@조력` 제거. **② 축적을 "승인제→자동"으로** — 메모리·위키·게시판 댓글·앱 프로파일은 승인 없이 바로 기록, 안전장치는 *사후 편집·되돌리기*(SOUL 변경만 확인 유지). **③ 메모리 재정의** — 개인 메모리 폐기, **공동 메모리(결정 로그) 한 장으로 일원화**(누구나 열람, 관리자 편집). **④ 위키 v2** — 섹션 누적·수정 이력·출처·검색/태그, 관리자 수정/삭제/되돌리기. **⑤ 지식 접근** — 전체 로딩 폐기, 색인 상주 + 상황별 retrieval(카파시식, 캐시 친화, 벡터 없음). **⑥ Azure OpenAI gpt-5.6-luna 품질 경로**(Secrets Store) + GLM 폴백. **⑦ 테스트 기간 초대→관리자.**
- v0.2 핵심 변경: ① AI를 "개인 비서"에서 "커뮤니티 운영자"로 재정의(6 운영 루프), ② 시뮬레이터 결정론 조립, ③ 헤르메스식 경량 MD 메모리, ④ 초대 링크 가입, ⑤ 회원 등급·관리자·탈퇴. 근거는 부록 A(결정 로그)·부록 B(스파이크 검증)
- 본문의 결함 번호(C1~C4 치명 · M1~M20 보통)는 v0.1 8차원 적대적 검토의 라벨로, 대응은 부록 A 결정 로그에 반영됨(별도 검토 파일은 폐기)

## 1. 비전

사회복지 실천가 30~50명이 바이브코딩과 AI 활용을 배우고, 앱을 만들어 공유하고, 서로 피드백하는 커뮤니티. **에이전트가 기본 내장된(agent-native) 사이트**로서, 구성원들이 따로 정리하지 않아도 에이전트가 대화와 게시물에서 지식을 길어 올려 위키와 온톨로지로 구조화한다.

핵심 철학 — **마중**: 실천가는 기술은 약하지만 말로 풀어내는 힘이 강하다. 이 시스템은 모델을 키우는 것이 아니라, 실천가 안에 이미 있는 암묵지를 끌어내 구조(온톨로지)에 앉힌다.

**v0.2 재정의 — AI는 개인 비서가 아니라 커뮤니티의 운영자다.** 개인 1:1 챗봇은 각자 쓰는 AI로 충분하므로 제공하지 않는다(과잉 제공 판정). 이 사이트의 AI는 공유 공간(채팅·게시판)에 살면서, 함께 대화하고 자료를 주고받는 과정을 위키·지식그래프·공동 기억으로 결정화한다. 차별화 지점(에이전트가 구성원 + 지식이 온톨로지로 축적 = 선례 공백)은 v0.1과 동일하며, v0.2는 그것을 구현 형태로 확정했다.

## 2. 사용자와 가입

### 대상
- 바이브코딩·AI 도구에 관심 있는 사회복지 실천가 30~50명 (모바일 iOS/Android 약 반반)
- 기술 숙련도 낮음 전제 — 온보딩 마찰 최소화가 최우선

### 인증·가입 [결정 D1 → D13 개정]
- **Google OAuth** 단일 로그인
- **초대 링크제 [D13]**: 구성원이 1회용 초대 링크를 발급 → 링크로 접속한 사람만 Google 로그인으로 가입. 이메일 allowlist는 운영자 부트스트랩용으로만 병행 (구현: `invite_links` 토큰, 사용 시 소멸)
- **실명제**: 가입 후 필수 프로필 — 성명/소속(필수), 부서/직급(선택 — 리뷰 M5)
- 프로필 열람·수정 페이지 제공. GitHub 계정은 필수 아님

### 회원 등급·탈퇴 [D14 신설]
- 등급 2단: **admin**(회원관리·강퇴·글 고정·모더레이션) / **user**. 위키·제안 승인 등 지식 활동은 개방 신뢰 유지(누구나). 시스템 계정 `agent` 별도
- **본인 탈퇴** + **관리자 강제 탈퇴**. 탈퇴 시 파기 절차(3장) 즉시 실행
- 관리자 페이지: 회원 목록(등급·소속·가입일·활동), 등급 변경(최소 admin 1인 보장), 강제 탈퇴

## 3. 개인정보·사례 정보 정책 [D2 유지 + 보강]

1. **커뮤니티 규칙**: 클라이언트 사례는 반드시 익명화해서만 언급 (가입 시 동의)
2. **PII 필터**: 에이전트 ingest(위키 결정화·프로파일 추론·메모리 갱신) 전 정규식 마스킹(주민번호·전화·이메일·계좌). 게시판 저장 전단에도 적용(리뷰 C3 — R1b)
3. **DM 제외 원칙**: DM은 AI 호출 불가 + FTS 인덱스 원천 제외(0002) + ingest 제외
4. **파기 절차 [D14]**: 탈퇴 시 — 세션·푸시구독 즉시 삭제, users PII 익명화(게시물 FK 때문에 행은 유지), R2 개인 메모리 삭제, 공동 메모리에서 개인 라인 제거. `actions_log`는 감사 목적 보존
5. **국외이전·처리위탁 고지**: Cloudflare 글로벌 망(D1/R2/DO) 저장 + LLM 처리(Azure OpenAI `gpt-5.6-luna` + Workers AI 폴백) — 처리방침에 명시(리뷰 C1·C2, R0 문서)
6. **정책 문서 3종 [초안 반영]**: `src/policies/{privacy,terms,consent}.md`를 vite `?raw`로 번들에 포함, 공용 `Markdown`으로 렌더(`components/Policies.tsx`). 로그인 화면·전 페이지 하단 `PolicyFooter`, 가입 프로필 화면 `PolicyModal`("전문 보기")로 연결. 회원 데이터 전용(클라이언트 당사자 동의는 각 기관 몫)이라 가이드 원본의 ③제3자제공·⑤민감정보 항목은 제외, ①수집·이용 / ②선택 / ③국외이전 / ④AI처리 구성. **모두 초안 — 정식 공개 전 전문가 검토 필요.**

## 4. 아키텍처 (구현 확정)

플랫폼: Cloudflare 서버리스. 프론트(React+Vite SPA, PWA)와 백엔드(Hono Workers)가 한 프로젝트, `@cloudflare/vite-plugin` 통합 빌드·배포.

```
[사용자 PWA]  React + Vite (welfareai.net — 현재 welfareai.rainbow-313311.workers.dev)
     │
[Cloudflare Workers — Hono 라우터]
  ├ 채팅       → ChatRoom DO + WebSocket Hibernation, D1 영속화, AI 멘션 참여(5장)
  ├ 커뮤니티   → D1: 게시물·댓글·채팅로그·위키·그래프·라벨·회원·세션·초대·제안
  ├ 이미지     → R2 welfareai-media (URL만 D1에)
  ├ 웹푸시     → VAPID + WebCrypto 라이브러리(@block65/webcrypto-web-push — 리뷰 M7)
  ├ 인격·기억  → R2: SOUL.md, memory/community.md (개인 메모리 폐기 — v0.3)
  └ LLM        → Azure OpenAI(품질) + Workers AI(폴백) — provider 계층(llm.ts)
```

### LLM [D15·D17·D26]
- **품질 경로(기본): Azure OpenAI `gpt-5.6-luna`** — OpenAI 호환 v1(`https://wcwf.services.ai.azure.com/openai/v1`), 키는 **Cloudflare Secrets Store 바인딩 `AZURE_OPENAI_KEY`**(`.get()`로만 읽음, 코드 비노출). reasoning `none|low|medium|high`. `getProvider`가 키 있으면 우선.
- **폴백 경로: Workers AI** — `@cf/zai-org/glm-4.7-flash`(추론, 한국어 양호). Azure의 **모든 메서드가 오류·타임아웃·빈 응답이면 자동 폴백**. GLM은 JSON/분류에 `enable_thinking=false`, 대화에 `reasoning_effort=low`, 25초 한도 초과 시 다시 `@cf/meta/llama-3.3-70b-instruct-fp8-fast`로 폴백(실측: GLM 전면 무응답 날 존재 — 부록 B).
- **구조화 출력은 제약 디코딩 [D17]**: JSON은 자유 생성 금지 — `response_format: json_schema`. (Azure/GLM 공통)
- **프롬프트 캐싱**: Azure 자동(≥1024토큰 접두 일치). 히트율은 프롬프트 접두 안정성으로 관리 — *안정 접두(SOUL+메모리+색인)=system / 가변 꼬리(retrieval 본문+대화)=user*.
- **호출 방식**: Azure·Workers AI 모두 REST(계정 소유 토큰은 바인딩 원격 프리뷰 불가 — CLAUDE.md).
- **금지**: Codex/ChatGPT OAuth 채널에 구성원 트래픽 연결 금지(리뷰 C2).
- 비용 상한: 월 $10~20 + 지출 알림

### 무료 티어·웹푸시
v0.1 4장의 무료 티어 수치와 웹푸시 전략(VAPID, iOS 16.4+ 홈 화면 설치, 카톡 인앱 탈출 안내)은 리뷰에서 전건 확인 — 그대로 유지.

## 5. 에이전트 설계 — 커뮤니티 운영자 [v0.2 전면 개정]

### 정체성 [v0.3 개명·이원화]
- 멘션 토큰은 역할명(정식 이름은 온보딩에서 함께): **`@지기`**(운영자 — 전체 메모리·위키를 읽고 소통 촉진·연결·자료 꺼내기 = 읽기) / **`@서기`**(기록자 — 대화를 정리해 메모리·위키에 기록 = 쓰기). `@조력`은 지기로 흡수.
- 인격·규칙은 **SOUL.md(R2)** 한 장 — 운영 탭에서 누구나 편집, 에이전트가 스스로 수정을 **제안**(SOUL만 HITL 유지)

### 행동 원칙 [D16 → v0.3 개정]
- **행동은 능동, 발화는 수동**: 공개 발화는 멘션 응답·예약 발행(소식)뿐. 무멘션 개입 금지, DM 호출 거부, 자기 메시지 무반응(루프 방지). 게시판 새 글엔 자동 연결 답글(발화지만 사람이 명시적으로 올린 글에 대한 반응).
- **축적은 자동, 안전장치는 사후 편집·되돌리기** [v0.3 전환]: 명시적 `@서기` 호출·게시판 글 등 **사람이 촉발한** 지식 축적(메모리·위키·태그·연결 댓글·앱 프로파일)은 승인 없이 바로 기록한다. 되돌릴 수 있는 문서라 사전 승인 대신 *직전 판 백업 + 운영자 손수정*으로 통제. **SOUL 자기수정만 HITL 유지**(정체성 변경이라). AI 산출물엔 항상 AI 표시.

### 운영 루프 (지기=읽기·연결 / 서기=기록)
| 루프 | 트리거 | 처리 | 통제 | 산출 |
|---|---|---|---|---|
| L1 기록 (서기) | `@서기` | 방 최근 대화(DM 제외) → PII 필터 → **주제별 1~3개 항목**으로 분할 → 목적지(메모리/위키) 판단 | **자동** + 되돌리기 | 위키 섹션 누적(출처)·공동 메모리 갱신 + 방 알림 |
| L2 연결 (지기) | 새 글 / `@지기` | 라벨 그래프 + 위키 retrieval → 비슷한 앱·지식 | **자동**(게시판 댓글) | AI 연결 댓글 |
| L3 대화 (지기) | `@지기` 멘션 | SOUL + 공동 메모리 + **위키 색인 + 상황별 retrieval** → 공개 답변 | 무승인(공개·AI 표시) | 공개 답변 → 모두가 학습 |
| L4 앱 프로파일 (서기) | 결과물 공유 게시 | 구조 추론 → 표준 라벨 정규화 | **자동 확정** | 그래프 기록 → 시뮬레이터 "N회 검증" |
| L5 소식·다이제스트 | 크론 (소식 주 2~3회, 다이제스트 주 1회) | 리서치 1건 / 주간 요약(DM 제외). *웹검색 아님 — LLM 지식 기반, 검색 API 확보 시 승격* | 자동 발행 | 소식 게시물 + RSS |
| L6 기억 갱신 | L1에 통합 | 공동 메모리 압축 병합(rewrite) | 자동 + 되돌리기 | community.md |

### 메모리·지식 3층 [D18 → v0.3 재정의]
- **SOUL**(인격, 거의 불변) / **공동 메모리**(결정 로그, 자주 갱신) / **위키**(지식 문서, 누적) — 셋은 **분리**. 위키가 도서관이라면 메모리는 "무엇을 정했나" 수첩.
- **개인 메모리 폐기** [v0.3]: `memory/{userId}.md`는 "개인 비서" 모델이라 컨셉과 안 맞아 제거. 메모리는 **공동 하나로 일원화**.
- **공동 메모리** `memory/community.md`: 커뮤니티의 결정·현재 상태 로그(헤르메스식 압축, ~15줄). 서기가 자동 기록, **누구나 열람**·관리자 편집·되돌리기(직전 판 백업). AI가 방·게시판 개입 시 항상 읽음.
- **지식 접근 = 색인 + retrieval(카파시식)** [v0.3]: 위키 전체를 컨텍스트에 넣지 않는다. **색인(제목·요약·태그)만 상주**(캐시 친화 안정 접두), 질문에 맞는 **본문만 결정론적으로 꺼냄**(FTS/LIKE+라벨, 벡터 없음). 매칭 실패 시 최근 문서 폴백. 캐시 히트를 위해 프롬프트를 *안정 접두(SOUL+메모리+색인)=system / 가변 꼬리(본문+대화)=user* 로 구성.
- 관리형 Agent Memory(private beta)는 계정 미승인(`10018` 실측) — 미사용.

### LLM 라우팅 [v0.3]
- **품질 경로: Azure OpenAI `gpt-5.6-luna`**(OpenAI 호환 v1, Secrets Store `AZURE_OPENAI_KEY`). reasoning none/low/medium/high. **모든 호출 실패 시 Workers AI(GLM)로 자동 폴백**. 구조화 출력은 `response_format: json_schema`.
- 프롬프트 캐싱은 Azure 자동(≥1024토큰 접두 일치) — 우리는 접두 안정성으로 히트율을 관리.

### 제거·격하 [D19 → v0.3]
- 개인 1:1 챗봇 제거(R2b) 유지. 개인 메모리도 폐기. 운영 탭 = **제안함(SOUL만)·인격(SOUL)·소식**(안내·설계 도우미 탭 제거 — 연결은 자동, 설계는 시뮬레이터+@지기). SOUL 편집은 **운영 탭**으로 이동.

## 6. 커뮤니티 기능

### 게시판 (한국형)
- 카테고리: 공지 / 결과물 공유(앱 공유) / 질문답변 / AI·바이브코딩 소식(에이전트) / 자유
- 마크다운 [D20]: 렌더 `react-markdown`+`remark-gfm`+`rehype-sanitize`(AI 출력 포함 전부 sanitize), 작성 `@uiw/react-md-editor`(미리보기+문법, lazy 로드). 클립보드 이미지 → R2
- R1b에서 완성: 글·댓글 수정/삭제(작성자·admin), 답글(parent_id), soft-delete, 조회수 1인 1회, 페이지네이션·정렬, '공지'는 admin만, **저장 전단 PII 필터(C3)**
- AI 게시판 관리(R3): 새 글 자동 태깅 제안, 질문답변 스레드 요약→위키 제안, 비슷한 앱 연결 코멘트 제안 — 전부 제안함 경유

### 실시간 채팅
- 전체방 + 주제 채널 + DM (방/채널/DM = DO 인스턴스 1개, Hibernation 필수)
- **AI가 방의 참여자**(5장 L1~L3). DM은 AI 호출 불가·ingest 제외
- "에이전트와 대화" 채널은 공개 채널 — 모두의 질문·답이 공유 자산이 된다

### 조합 시뮬레이터 — 결정론 조립 [D17, 스파이크 검증 완료]
- **설계도는 "생성"이 아니라 "조립"**: 표준 라벨마다 **레시피 카드**(`labels.meta_json` — 엔티티: 표준 필드·테이블 / 패턴: 필요 테이블·화면·스택·유의점)를 두고, 선택 조합을 코드가 병합해 마크다운 설계도(스키마 DDL·화면·스택·PRD 초안)를 만든다. LLM 무관 — **같은 조합은 항상 같은 결과, 잘림·수식어·환각 원천 불가**
- **커뮤니티 검증 표기**: 그래프에서 "이 재료를 공유하는 앱 N건 — ○○님" 결정적 조회. 없으면 "첫 발견 🏆"
- **유연성 밸브 2개**: ① 팔레트에 없는 재료는 직접 입력 → 표준 어휘 정규화 → 어휘 밖이면 제약 디코딩으로 임시 카드 생성, 설계도에 **⚠️ 미검증** 표시로 포함 + `labels(proposed)` 큐 → 승인 시 정식 카드(팔레트 성장). ② 기관별 변주는 @지기 대화로 — "진입은 놀이로, 심화는 대화로"
- **성장 플라이휠**: 앱 공유→프로파일 자동 확정→그래프(검증 카운트↑·새 라벨 제안) / 대화→위키→카드 참고 / 직접 입력→proposed 큐. **모델이 아니라 데이터가 자란다**
- md 다운로드 → 바이브코딩 도구 입력. 게임 질감(OriginKit)은 R4

### 위키 v2 + 공동 메모리 [v0.3]
- **위키**: 서기가 **섹션 누적**으로 기록(기존 문서는 통째 재작성 대신 `출처 붙은 섹션 append` — 이전 기여·출처 보존). 문서마다 `summary`(색인용 한 줄)·`source`(출처)·`prev_*`(되돌리기 1회) + **수정 이력**(`wiki_edits`: 누가·언제·무엇을·출처). 관리자 **수정/삭제/되돌리기**.
- **열람/탐색**: 목록은 제목+요약(색인), **검색(`?q=` LIKE)·태그 필터·정렬**, `GET /api/wiki/:id.md` raw. 그래프 통계는 접기(부차적).
- **공동 메모리**(위키 탭 상단): 결정 로그, 누구나 열람·관리자 편집/되돌리기.
- 그래프는 **앱 구조 프로파일**용(엔티티·패턴·도메인 — 시뮬레이터 "N회 검증"·연결). 앱 공유 시 자동 확정 기록.
- 향후(규모 확대 시): 섹션이 이미 조각이므로 옵시디언식 원자 노트+링크로 승격 가능. 한국어 FTS는 리뷰 M12대로 재검토.

## 7. 지식 구조 — 표준 라벨 + 레시피 카드 + 경량 그래프

레시피 모델: **재료(엔티티) × 조리법(패턴) → 요리(앱)**. v0.2에서 각 라벨에 **레시피 카드**가 붙어, 어휘가 "이름 목록"에서 "조립 가능한 지식"이 되었다.

- **표준 라벨 어휘**: 도메인 8(추천 조합 포함) / 엔티티 20 / 패턴 20 시드(무지개 큐레이션). 에이전트·직접입력은 새 라벨을 **제안만** — 승인 시 정식
- **앱 구조 프로파일**: 결과물 공유 게시 시 서기가 추론(제약 디코딩) → **자동 확정** → 그래프 기록
- **경량 그래프**: D1 nodes/edges (앱·도메인·엔티티·패턴·사람 / 사용한다·구현한다·만든이·속한다). 매칭은 결정적·설명 가능("엔티티 2개·패턴 1개 공유")
- **검색**: 벡터화 불채택 유지 — 라벨 정규화 + 그래프 + FTS5 (한국어 형태소 한계는 리뷰 M12, 필요 시 재검토)
- D1 스키마의 원본은 `migrations/` 0001~0007 (v0.1의 골격 스키마 서술은 폐기)
