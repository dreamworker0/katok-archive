# 보고서 링크·사진 문맥 연결 디자인

## 목표

현재 164개 보고서와 앞으로 생성되는 모든 보고서에서 링크·사진·첨부를 관련 문단 바로 뒤에 배치한다. 보고서 문장은 바꾸지 않고, 연결 근거가 약한 자료는 잘못 붙이지 않는다.

## 현재 문제

- 링크는 원본 메시지에서 본문과 함께 공유됐어도 보고서에 호스트명이 직접 적혀 있지 않으면 카드 하단의 링크 목록으로 내려간다.
- 사진·첨부는 보고서에 `![[메시지 ID]]` 자리표를 사람이 적은 경우에만 문단 사이에 들어가고, 나머지는 보고서 끝에 모인다.
- `t-162`의 `msg-001480`은 AI 윤리 문장과 YouTube 링크가 같은 메시지인데도 링크가 보고서 끝에 나타난다.

## 설계 원칙

1. 기존 마크다운 보고서를 원본으로 유지하고 문장이나 제목을 자동 수정하지 않는다.
2. 원본 메시지 전체를 브라우저 발행본에 추가하지 않는다.
3. 빌드 시점에만 원본 메시지를 보고서 블록과 대조하고, 발행본에는 메시지 ID 자리표와 이미 공개 대상인 링크·미디어 메타데이터만 남긴다.
4. 사람이 적은 `![[msg-...]]` 미디어 자리표가 자동 추론보다 우선한다.
5. 충분한 근거를 얻지 못한 링크·사진·첨부는 기존처럼 보고서 하단에 모은다.
6. 같은 자료를 문단 안과 하단에 중복 표시하지 않는다.

## 문맥 판정

### 링크

- URL을 제거한 원본 메시지 본문과 보고서의 문단·인용문·목록 블록을 정규화해 비교한다.
- 공백과 마크다운 강조 기호를 제외한 문자열이 서로 포함되거나, 독립적으로 계산한 유사도가 기준 이상일 때만 해당 블록을 선택한다.
- 같은 메시지에 여러 URL이 있으면 하나의 문맥 카드에 함께 표시한다.
- 선택된 블록 뒤에는 빌드 발행본에만 `![[link:메시지 ID]]` 자리표를 삽입한다.

### 사진·첨부

- 보고서에 기존 `![[메시지 ID]]`가 있으면 그 위치를 그대로 사용한다.
- 자리표가 없는 미디어 메시지는 같은 스레드의 바로 앞뒤 텍스트 메시지를 최대 두 칸까지 살펴본다.
- 가까운 메시지의 작성자가 같고 그 텍스트가 보고서 블록과 높은 유사도로 대응할 때만 자동 자리표를 삽입한다.
- 앞뒤 후보가 비슷한 점수를 얻거나 기준에 못 미치면 하단 묶음에 남긴다.

## 화면 표현

- 문맥 링크는 관련 문단 바로 아래에 따뜻한 표면색의 작은 카드로 표시한다.
- 카드에는 링크 아이콘, 호스트명, 전체 URL, 공유자와 날짜를 표시한다.
- 외부 페이지의 제목이나 썸네일을 가져오기 위한 추가 네트워크 요청은 하지 않는다.
- 문맥 사진은 현재 인라인 사진 레이아웃을 유지하되 공유자·날짜·시간 캡션을 함께 표시한다.
- 하단에는 연결하지 못한 자료만 `이 주제에서 함께 공유된 자료`라는 중립적인 제목으로 표시한다.

## 접근성·보안

- 링크 카드는 실제 `<a>` 요소이고 새 창 열림에 `rel="noopener noreferrer"`를 사용한다.
- 장식 아이콘은 `aria-hidden="true"`로 처리한다.
- URL과 메시지 ID는 HTML 이스케이프 후 출력한다.
- 원본 메시지 본문, 이메일, 인증 정보는 새 발행 필드에 포함하지 않는다.

## 검증 기준

- `t-162`의 YouTube 링크가 `AI 윤리로` 인용문 바로 뒤에 나타나고 하단 링크 목록에서는 빠진다.
- 수동 미디어 자리표의 위치는 바뀌지 않는다.
- 명확한 문맥이 없는 자료는 하단에 남는다.
- 링크·사진·첨부가 중복 표시되지 않는다.
- 모든 기존 보고서가 오류 없이 빌드되며 원본 메시지 본문이 발행본에 새로 포함되지 않는다.
