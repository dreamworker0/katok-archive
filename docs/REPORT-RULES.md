# 보고서 규칙

주제 보고서(`output/reports/t-XXX.md`)를 어떻게 쓰는가. **사람이 손으로 쓸 때도,
밤 자동 갱신이 쓸 때도 같은 규칙이다.**

## 규칙 원본은 코드에 있다

규칙 문장 자체는 `scripts/topic_reports.py` 의 `REPORT_RULES` 하나뿐이고, 보고서를
쓰는 두 프롬프트가 **그것을 그대로 읽는다**.

| 쓰는 곳 | 언제 | 프롬프트 |
|---|---|---|
| 분류하면서 함께 | 매일 밤 23:40 새 대화 | `classify_unsorted.build_prompt` |
| 보고서만 다시 | 사람이 불러서 (`--rewrite-*`) | `classify_unsorted.build_report_prompt` |

이 문서에 규칙을 옮겨 적지 않는 이유: **예전에 규칙이 두 곳에 따로 적혀 있어서
사고가 났다.** 분류 프롬프트에는 "링크나 사진 자리표를 넣지 마세요. 자료는 화면
아래에 따로 붙습니다" 만 있었고 인용·절 규칙은 다른 프롬프트에만 있었다. 그래서
2026-07-27 밤 자동 갱신이 만든 보고서는 한 덩어리 산문이고 사진·링크가 전부 글 끝에
모였다. 314편 중 32편이 그 상태였다. 규칙은 한 군데만 있어야 한다.

## 지켜야 하는 두 가지

`scripts/topic_reports.py` 의 숫자와 검사가 같은 값을 본다.

- **인용** — 대화 `QUOTE_REQUIRED_FROM`(6)건 이상이면 짧은 인용(`>`)이 하나는 있어야
  한다. 한 인용은 `MAX_VERBATIM_CHARS`(40)자를 넘기지 않는다.
- **절 나눔** — 대화 `SECTION_REQUIRED_FROM`(10)건 이상이면 `## 짧은 제목` 으로
  나눈다.

### 인용이 왜 규칙인가 — 사진·링크의 자리를 정하는 일이다

사진·링크·첨부는 `place_context_anchors` 가 **인용을 기준으로** 본문 사이에 끼운다.
인용이 없으면 끼울 자리가 없어 **자료가 전부 글 끝으로 밀린다.** '글 따로 자료 따로'가
되는 것이고, 읽기 불편하다는 지적이 정확히 이것이었다.

그래서 자료가 오간 대목을 인용으로 짚는 것이 곧 그 자료의 자리를 정하는 일이다.
`![[...]]` 자리표를 손으로 넣지는 않는다 — 없는 자료를 가리켜 화면이 깨진다.

## 어긴 것을 어떻게 찾고 고치나

발행할 때마다 검사해서 알려준다.

```
[주의] 구조 규칙을 어긴 보고서 32개 — 고치려면 …
```

고치는 명령 (한 번에 N편, LLM 값이 든다 — 2026-07-28 실측 편당 약 $0.15):

```bash
python -m scripts.classify_unsorted --rewrite-unstructured 5
```

**매일 돌리지 않는다.** 규칙이 프롬프트에 들어간 뒤로 새 보고서는 규칙을 지키므로,
이 명령은 규칙이 없던 시절의 보고서를 사람이 불러 정리하는 용도다. 새로 쓴 보고서가
규칙을 어기면 그 자리에서 `[규칙 미달: … 없음]` 이라고 로그에 찍힌다.

## 분량은 따로 본다

구조와 분량은 다른 검사다. 분량은 `MIN_BODY_BY_COUNT`(대화 건수별 최소 글자)로 보고
`--rewrite-thin` 으로 고친다. **길게만 쓴 한 덩어리 산문은 분량 검사에 안 걸린다** —
그것을 잡는 것이 위의 구조 검사다.
